# SetCatcher Release Boundaries

Last updated: August 14, 2026.

## Private Beta 1 — prove trust

Ship only when:

- a clean external Mac can install and launch normally;
- Folder Protection preserves a completed recording and leaves the source unchanged;
- protection and failure states are understandable without developer help;
- Library and set context survive relaunch;
- diagnostics are privacy-safe and useful;
- Serato and rekordbox setup paths are tested with external users;
- Capture failures preserve a clear Folder Protection or Input device fallback.

Included:

- full Mac window and menu-bar status;
- onboarding and folder permissions;
- Folder Protection and manual scan;
- local archive, sidecars, Library, search, filters, and set context;
- App audio Capture and Input device Capture as beta capabilities;
- supported history import and matching;
- optional account/device/license support;
- local diagnostics and explicit metadata upload;
- local publish-pack export;
- invite-only waitlist and cohort measurement.

## Private Beta 2 — prove repeated value

Prioritize improvements discovered in Beta 1:

- onboarding and permission recovery;
- app-specific setup clarity;
- Capture route detection and fallback guidance;
- automatic-history match quality;
- archive receipts and confidence signals;
- support tooling and issue categorization.

Exit when at least 40% of activated testers protect a second real set within 30 days and critical source-integrity issues remain at zero.

## Open Beta — prove acquisition and breadth

Add only after clean installation and support load are stable:

- public beta download;
- broader community recruitment and referral loops;
- more representative Traktor, VirtualDJ, djay Pro, and hardware testing;
- pricing and packaging experiment without removing access to existing beta data;
- dedicated SetCatcher domain and production account configuration.

## Post-beta candidate work

- paid local license and optional major-upgrade model;
- remote archive backup after explicit opt-in;
- richer publish/export workflows;
- Windows feasibility and demand validation;
- expanded hardware recipes and device verification;
- deeper audio-quality analysis;
- iPad product validation as a separate workflow.

## Research only

Do not put these on a committed customer roadmap until their supported integration path and policy posture are verified:

- VirtualDJ native plugin binary;
- Traktor QML/CSI injection;
- Serato private or legacy binary APIs;
- UI automation inside DJ applications;
- streaming-service recording workarounds;
- automatic public publishing;
- Mac-to-iPad archive synchronization.

## Scope-change rule

Any addition to Beta 1 must either replace another item or explicitly extend the release timeline. A feature is not Beta 1 merely because code exists; it belongs there only if it improves the core protection promise and can be supported honestly.
